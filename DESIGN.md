# Design System: Bud Decision Studio

## Overview

**Creative North Star: "The Quiet Instrument"**

Bud Decision Studio is a native desktop app that happens to run in a browser and ships in a Tauri window. The window is filled edge to edge at every size: a sidebar, a titlebar that doubles as the drag region, content panes that scroll on their own, and a status bar at the foot, arranged after LM Studio. The surfaces are macOS-grade: a soft grey ground, white surfaces lifted by a half-pixel ring and a whisper of shadow, hairline separators, Apple-style segmented controls, switches and sliders. Every screen has one job, shows the few things that matter first, and keeps depth one click away in an inspector, a segmented tab, a disclosure row or a popover.

Colour is spent almost entirely on meaning. Bud violet is the accent and the answer: it marks the primary action, the selected row, the menu highlight and, in every figure, the winning option. Orange means one thing, "Ask a human" and its cautions. Green and red only report status. Everything else is grey, white and text. Density is desktop density (13.5px body, 28px controls, 42px grouped rows) because the audience sits at this app for long sessions beside an editor and a terminal.

The decision figure is the signature. Each answer is drawn once, on a shared 0 to 100% axis, with the answer stated large, a one-sentence caption that says what the plot shows, and one verdict: act automatically or ask a human. Data moves in (bars grow, digits roll) on a slower data curve, while the interface around it responds quickly and quietly.

**Key Characteristics:**
- Full-window shell: 232px sidebar, 48px titlebar, 30px status bar, panes that scroll independently.
- Grey ground, white surfaces, hairline lines; depth from a 0.5px ring plus soft shadow, never from borders alone.
- One violet for accent, selection and the answer; a three-step violet data ramp; orange reserved for asking a human.
- System font first (SF Pro on macOS), self-hosted Inter elsewhere, Geist Mono for code.
- Figures: answer, shared axis, one-sentence caption, one verdict.
- Both themes from the same token names; motion off under reduced motion.

## Colors

A neutral Apple-grey ground and white surfaces, with Bud's violet carrying accent and answer and a single warm orange held back for "ask a human".

### Primary
- **Bud Violet** (`accent`, also `data-3`): the one accent. Primary buttons, the Decide button, switch and slider fills, focus rings (45% mix), input focus borders, menu highlight, the selected table row tint, nav icons, the round plus badge on the Create new Decision panel, the answer mark in each type-tile miniature, checkbox and radio fills, the current setup step dot, the setup progress fill, and the winning bar, column, stem or dot in every figure. In dark mode it lightens to the `accent-dark` value so it keeps contrast on charcoal.
- **Violet Ink** (`accent-text`): violet used as text or small marks on light fills: links, plain buttons, accent chips, question-type pills, the estimate line in number plots.
- **Violet Wash** (`accent-tint`, `accent-tint-2`): the selected-row fill, accent chip ground, the 80% band in number plots, and the hover ring on clickable cards. Also the ground of the two invitation panels (Create new Decision, and "Next, choose your models" in setup), the ticked row in the model chooser, and the selected radio card in setup. Also the text selection colour.

### Secondary
- **Violet Data Ramp** (`data-1` light, `data-2` mid, `data-3` deep): Bud's logo violets as the only data colours. `data-1` for resting options, `data-2` for the runner-up and secondary series (latency bars, per-model breakdowns, the span in comparison dumbbells), `data-3` for the answer and primary series.

### Tertiary
- **Ask Orange** (`orange` mark, `orange-text` text, `orange-tint` wash): "Ask a human" and caution only. The gate label under a figure, the winning bar when the answer falls below the act threshold, the "Leaning"/"Unsure" chip when the gate says ask, question-quality tips, "watch" points in model notes, the budget line in evaluation charts, the "Experimental" chip on a device in setup, the setup hardware warnings, and the not-enough-disk warning in the model chooser footer.

### Neutral
- **Window Ground** (`ground`): behind cards and panes; the Playground answers half.
- **Surface White** (`surface`): cards, grouped lists, figures, inspectors, titlebar, status bar, menus, dialogs, the loader palette.
- **Quiet Fill** (`surface-2`): a recessed fill inside a surface: code bodies, JSON trees, figure tracks, table hover, palette bars.
- **Control Fills** (`fill`, `fill-2`): segmented tracks, chips, option pills, quiet button hover, slider and switch tracks (`fill-2`), scrollbar thumbs.
- **Sidebar Lilac-Grey** (`sidebar`): the sidebar only, with `sidebar-hover` and `sidebar-select` as translucent grey-violet overlays for nav and loaded-model rows.
- **Hairlines** (`line`, `line-2`): `line` for input strokes, table heads and plot baselines; `line-2` for every separator: grouped-row insets, pane edges, figure caption rules, the 25% grid inside plots.
- **Text Ramp** (`text`, `text-2`, `text-3`): `text` for content and answers; `text-2` for secondary text, labels, axes and captions (5.6:1 on white); `text-3` for icons, chevrons and decoration only.
- **Status Green and Red** (`green*`, `red*`): loaded-model dots, live indicator, OK and failed tags and chips ("On this computer" in the chooser), "Act automatically", failed requests in the timeline, error toasts, the danger button text, and in setup the done step dots, the done and failed checklist marks, the ready check and the error notes.
- **Code Syntax** (`code-*`): Xcode-like keyword, string, number, comment, key and function colours, used inside code blocks and JSON only.

### Named Rules
**The Violet Is the Answer Rule.** Bud violet marks the one thing that matters on a surface: the primary action, the selection, the winning option. If two things on a screen are violet, one of them is the answer and the other is the way to get it.

**The Orange Means Ask Rule.** Orange is spent on "Ask a human" and caution, nothing else. Never use it for branding, highlights or decoration.

**The Status-Only Rule.** Green and red report state (ready, OK, failed, error). They never colour data series or decorative marks.

**The Code Colours Stay in Code Rule.** Syntax colours appear inside code and JSON blocks only; they never leak into charts, chips or UI.

## Typography

**Display Font:** the system UI font (SF Pro on macOS), with self-hosted Inter (variable, SIL OFL 1.1) as the fallback everywhere else
**Body Font:** the same stack
**Label/Mono Font:** SF Mono on macOS, then self-hosted Geist Mono (SIL OFL 1.1), for code, JSON, endpoints, request ids and addresses

**Character:** One quiet sans carries every role, as a native app would; hierarchy comes from size, weight and slightly tightened tracking, never from a second display face.

### Hierarchy
- **Display** (700, 34px, 1.1, -0.03em): the Learn page hero only.
- **Headline** (700, 24px, -0.022em): page titles on scrolling pages.
- **Answer** (650, 22px, 1.2, -0.02em, tabular): the answer in a figure and the big numbers in stat strips (18px in the slim Activity strip, 20px in evaluation metrics).
- **Title Large** (700, 19px, -0.02em): the model inspector hero and Learn section heads; 16 to 17px for request inspector heroes and empty states.
- **Titlebar** (600, 15px, -0.01em): the page title in the titlebar, with a 13px secondary note beside it. The 15px figure percentage beside an answer uses the same size at 500.
- **Title** (600, 13.5px): pane heads, inspector heads, card titles (14px in chart cards).
- **Body** (400, 13.5px, 1.45, -0.003em): all running UI text; tables and menus at 13px; the situation box and question text at 14px; Learn prose at 14.5px/1.6 within 62ch.
- **Label** (600, 12.5px, `text-2`): field labels, group titles, inspector section heads, spec section titles. Sentence case.
- **Caption** (400, 12 to 12.5px, `text-2`): help text, figure captions, table heads, status bar, chips.
- **Tick** (400, 11px, tabular, `text-2`): axis ticks and chart labels.
- **Code** (400, 12.5px, 1.65): code blocks and JSON trees; 11.5px in status bar and chip code.

### Named Rules
**The System First Rule.** The font stack always starts with the platform UI font; Inter and Geist Mono are the self-hosted fallback so the app works offline in any window.

**The Tabular Numbers Rule.** Every number that can change or be compared (percentages, latencies, sizes, counts, axis ticks) is set with tabular figures.

## Layout

The app is a CSS grid that fills the viewport and never scrolls as a whole on desktop: a 232px sidebar spanning the titlebar and content rows, a 48px titlebar over the content, and a 30px status bar across the full width. The content area hands its height to a view; views split into panes separated by a `line-2` hairline, and each pane scrolls on its own with a sticky 48px pane head that is translucent (88% ground or surface with a saturate-and-blur backdrop).

- **Playground:** two equal halves, after the layout the client preferred. The left half is a white work surface: a top row with the model button (opens the Ctrl+L loader) and Examples, then State with a Text/JSON switch and a bordered text box, then Questions as bordered cards joined by a thin branch line on the left (options flow as chips across the row, scale and value presets inline), and a pinned full-width Decide bar. The right half, on the window ground, has underlined tabs (Answers, JSON, Code), the run summary line, and answers stacked one per row at full width, each numbered in mono ("Fig. 1a") on a bordered white card. Decision settings open as a 320px panel that slides over the answers, so the halves stay equal.
- **Playground, Create new Decision:** under the question cards, a 14px-radius violet-wash panel holds the six question-type tiles in an auto-fill grid (min 150px per tile); elsewhere the tile grid is three columns, two below 860px.
- **Models:** a table pane plus a 360 to 440px inspector with a hero, actions and a full-width segmented tab bar (Overview, vs Jev, Load).
- **Activity:** a controls head (live state, time range, filters), a slim four-up stats strip, one chart card whose segmented control switches Timeline, Models, Clients and Formats, a request table, and a 380 to 460px inspector that redraws the selected request's answers with Answers, Request and Response tabs.
- **Evaluate:** a 360 to 440px setup column and a results column.
- **Scrolling pages** (API, System, Learn) use 22px 26px 40px padding, a 24px headline with a 72ch lede, and auto-fill card grids (min 380px, or 520px for wide cards).

- **Sheets:** modal dialogs are centred with a dim backdrop, 16px radius and the pop shadow. The model chooser is the wide sheet (up to 820px, at most 760px tall): a fixed head with title, lede and quick-select row over a `line-2` rule, a list that scrolls on its own, and a fixed `surface-2` footer with the summary on the left and buttons on the right. Below 700px the rows drop the input and parameter columns and the footer summary takes its own line.
- **Desktop setup:** a separate full-window surface laid out like the macOS Installer: a 250px `sidebar`-coloured rail with the Bud mark, the four steps and the version at the foot, and a white page on the right with one question per page (26px/650 heading, 15px `text-2` lede, content held to 760px, 44px 52px 28px padding) over a `surface-2` footer bar with a note on the left and Back and the primary button on the right. Below 760px the rail becomes a top bar showing only the brand. Later launches show a centred splash instead.

Rhythm is a 4px-derived scale: 6 and 8px gaps inside controls, 10 to 14px between stacked cards, 16px pane padding, 16 to 18px card padding, 42px grouped rows.

Responsive behaviour keeps the window filled. The Playground's settings panel always floats over the answers with a pop shadow. Below 1320px side inspectors on other pages narrow to 340 to 400px. Below 1080px the sidebar collapses to a 64px icon rail. Below 860px the shell stacks: titlebar, a horizontally scrolling nav strip with labelled icons (fading at the right edge), then content that scrolls as one page, with panes and inspectors stacked in reading order.

### Named Rules
**The Full Window Rule.** Every screen fills the window at every size. No centred web-page columns, no max-width wrappers around the app.

**The Depth One Click Away Rule.** Show the few things that matter first; put detail in an inspector, a segmented tab, a disclosure row or a popover, not on the page.

**The Panes Scroll Alone Rule.** On desktop the shell never scrolls; each pane owns its scroll and keeps its head sticky.

## Elevation & Depth

A hybrid of tonal layering and soft, ring-led shadows. White surfaces sit on the grey ground; each carries a 0.5px ring that defines its edge plus a small, low-opacity shadow that lifts it. Controls get a slightly crisper ring. Only floating layers (menus, the loader palette, dialogs, toasts, tooltips, the overlay inspector) take the large, diffuse pop shadow. Nested surfaces inside a card drop their shadow and use `surface-2` instead. In dark mode the ring turns to white at low opacity and the shadow deepens. Pane heads use translucency with backdrop blur, not shadow.

### Shadow Vocabulary
- **Card** (`box-shadow: 0 0 0 .5px rgba(20, 16, 40, .07), 0 1px 3px rgba(20, 16, 40, .06)`): cards, grouped lists, figures, the model chip, question cards, stats strips, chart cards.
- **Control** (`box-shadow: 0 0 0 .5px rgba(20, 16, 40, .14), 0 .5px 1.5px rgba(20, 16, 40, .12)`): secondary buttons and the selected segment.
- **Pop** (`box-shadow: 0 0 0 .5px rgba(20, 16, 40, .12), 0 16px 40px rgba(20, 16, 40, .16), 0 3px 8px rgba(20, 16, 40, .08)`): menus, the loader palette, dialogs, toasts, tooltips, the overlaid inspector.
- **Accent ring** (`box-shadow: var(--shadow-card), 0 0 0 1px to 2px var(--accent-tint-2)`): hover on clickable cards and the question card being read. Question-type tiles ring their miniature at 1.5px, 55% violet, on hover; the selected setup radio card replaces its shadow with a solid 1.5px violet ring.
- **Inset violet ring** (`box-shadow: inset 0 0 0 1px` violet at 20%): the edge of the violet-wash invitation panels, which sit flat on the page with no drop shadow.

### Named Rules
**The Ring Before Shadow Rule.** Every elevated surface starts with a half-pixel ring; the drop shadow is secondary and soft. No hard or offset shadows.

**The Pop Is for Floating Things Rule.** The large pop shadow belongs only to layers that float above the window.

**The Invitation Panel Rule.** A violet-wash panel with an inset violet ring invites the next step (Create new Decision, the next-up panel in setup). What sits inside it is flat: no cards inside the card. It sits flat, without a drop shadow, and appears at most once per surface.

## Shapes

Continuous, gently rounded corners that grow with the size of the object: 6px for chips, small buttons and segments; 7px for standard controls, nav rows and inputs; 8px for segmented tracks, tooltips and thumbnails; 9px for loader and chooser rows; 10px for menus, notes, code blocks, question-type tiles and the Decide button; 12px for cards, grouped lists, figures and setup radio cards; 14px for the loader palette and the Create new Decision panel; 16px for dialogs and the chooser sheet. Round things are fully round: switch knobs, slider thumbs, status dots, step numbers, the plus and next-up badges, setup step dots, checklist marks and the ready check. Separators are 1px hairlines, inset from the left edge in grouped lists (14px, or aligned past an icon). Plot bars are pill-ended; histogram columns round only their tops (6px top, 2px base).

## Components

### Buttons
Quiet, native and compact.
- **Shape:** gently rounded (7px), 28px tall; small 24px (6px radius), large 36px (9px radius).
- **Primary:** Bud violet with white text, a faint violet under-shadow, 500 weight at 13px. The Decide button is the full-width large form (38px, 10px radius, 14px).
- **Secondary:** white with the control shadow; hover to `surface-2`.
- **Quiet:** transparent, hover to `fill`. **Plain:** violet text, hover to a violet wash. **Danger:** red text on the secondary form.
- **Hover / Active:** 160ms background change; press scales to 98.5% for 80ms. Disabled at 45% opacity.
- **Icon buttons:** 28px square, `text-2` icon, hover to `fill`; pressed state keeps the fill and turns the icon violet. Icons are Phosphor regular, inlined as SVG.

### Segmented Control
The main way to switch views and tabs. A `fill` track (8px radius, 2px padding) holding 24px segments at 12.5px/500; the selected segment is white with the control shadow (`fill-2` in dark). Full-width variant for inspector tab bars.

### Switch and Slider
- **Switch:** 34 by 20px track in `fill-2`, 16px white knob with a small shadow; on turns the track violet and slides the knob with the standard ease.
- **Slider:** 4px track in `fill-2` with the filled part in violet up to the thumb; 18px white thumb with a ring and soft shadow. Paired with a right-aligned 76px number field in a two-column row.

### Chips
- **Style:** 22px tall, 6px radius, 12px/500, tinted fill with matching text: neutral (`fill`/`text-2`), violet, orange (ask), green (OK), red (danger), and a mono variant for identifiers. Small 18px tag chips sit inline after model names.
- **State:** certainty chips use four fixed words: Very sure and Fairly sure in violet, Leaning neutral, Unsure in orange; whenever the gate says ask, the chip turns orange whatever the word.

### Cards / Containers
- **Corner Style:** 12px.
- **Background:** `surface` on `ground`; nested blocks use `surface-2` with no shadow.
- **Shadow Strategy:** card shadow (see Elevation & Depth).
- **Border:** none; the half-pixel ring does the work.
- **Internal Padding:** 16px 18px (14 to 16px for compact cards).

### Grouped Lists
macOS-style settings groups: a white 12px container, rows at least 42px tall with 8px 14px padding, key on the left and value right-aligned in `text-2`, separated by `line-2` hairlines inset 14px from the left. A 12.5px `text-2` group title sits above. Clickable rows hover to `surface-2`.

On the System page the **Where models run** group has three rows: "Run models on" with a segmented control of the devices this computer can use (a lightning icon for each GPU, a chip icon for the processor), "Installed engine" with the PyTorch version and setup date as help text and a secondary "Run setup again" button in the desktop app (the `./install.sh` command in mono when running from source), and "Models folder" with the folder's path in mono and a line of help text, a secondary "Change…" button (hard-drive icon) and, when a folder other than the Hugging Face cache is chosen, a quiet "Use the default" button. A folder whose disk is not connected says "Not available." in `red-text` at the start of the help text; while a model downloads, both buttons are disabled and the help text says why.

### Inputs / Fields
- **Style:** white, 1px `line` stroke, 7px radius, 6px 10px padding, 30px minimum. Label above at 12.5px/600, help below at 12.5px `text-2`. Selects draw a small chevron; search fields are borderless `fill` pills with a leading icon.
- **Focus:** border turns violet with a 3px 22% violet halo, 160ms. Caret is violet.
- **Option pills:** 26px `fill` pills with the name at 500 and description in `text-2`; the add field is a dashed outline that turns solid violet on focus.

### Menus and Popovers
White, 10px radius, pop shadow, 5px padding. Items are 6px-radius rows with a violet icon; hover or keyboard focus fills the row with solid violet and turns text and icon white, as in macOS menus. Group labels at 11.5px/600 `text-2`. Tooltips are dark in both themes (8px radius, 12.5px), with a bold term line for glossary entries.

### Tables and Row Actions
macOS list style: 12px sticky heads at 500 in `text-2` over a `line` rule, 13px cells with `line-2` row rules, tabular numeric columns right-aligned. Hover rows take `surface-2`; the selected row takes the violet wash. Row actions stay hidden until the row is hovered, selected or focused (always visible on touch). A model that does not fit the current device shows "Needs a GPU" (on the processor) or "Too large here" in `text-2` where Load or Download would be, with the reason in a tooltip; the loader palette shows the same words as a neutral chip, and the model inspector gives the full reason in place of the actions.

### Navigation
- **Sidebar:** lilac-grey `sidebar` fill with the Bud mark (22px) and "Bud Decision Studio" at 14px/650 in a 48px brand row; labelled nav rows at 32px, 500 weight, 18px violet icons; section labels (Developer, Help, Loaded) at 11.5px/600 `text-2` in sentence case. Hover and current use translucent grey-violet overlays, not violet. Loaded models list below with a status dot, size, and an eject button that appears on hover.
- **Titlebar:** white, page title at 15px/600 plus a 13px `text-2` note, icon buttons on the right; the whole bar is the Tauri drag region.
- **Status bar:** white, 12px `text-2`: GPU and load, a memory meter (violet for loaded models, grey for other programs), models on disk, download progress, and the API address in a mono pill.
- **Mobile:** a horizontal strip of icon-over-label items under the titlebar.
- **Brand assets:** `ui/brand/bud-mark.png` (sidebar mark), `favicon.png` and `app-icon.png` are crops or compositions of the client-supplied Bud lockup `bud-lockup-color-white.png` at the repo root; nothing is redrawn. The mark keeps its own colours in both themes.

### Model Loader Palette
After LM Studio's Ctrl+L: a centred white panel (up to 880px, 14px radius, pop shadow) at 10vh with a dim backdrop. A 52px search row at 16px, a `surface-2` bar with a sort segmented control, one aligned grid row per model (logo, name and maker, context, inputs, size, lifecycle, status), active row in `fill`, current model in the violet wash, and a footer with a "Choose load settings first" switch and key hints in `kbd` pills. Enters with a 180ms rise.

### Create new Decision Panel
The Playground's question-type picker, an invitation rather than a toolbar. A violet-wash panel (14px radius, 14px padding, inset violet ring, no drop shadow) under the question cards. Its head is the heading "Create new Decision" at 15px/600 in `accent-text` and a one-line 12.5px `text-2` explanation held to 60ch. Below sit six flat tiles (transparent, 10px radius, 8px padding), one per question type. Each tile opens with a 40px white miniature (8px radius, card shadow), the only framed element in the panel, that draws the answer that type produces in the figure's own vocabulary: three bars with the first in violet, a five-dot scale with the fourth dot enlarged in violet, a yes bar filled to three quarters over Yes and No labels, two ticked violet boxes and one empty, three numbered ranked bars, and a range with a violet band and estimate line. The type name follows at 13px/600, then one short 11.5px `text-2` sentence ("One option from a list.", "All options, most likely first."). Hover fills the tile white and rings its miniature in 55% violet over 120ms; press scales to 98%; focus shows a 2px violet outline.

### Model Chooser Sheet
"Choose models to download": nothing downloads until the person chooses. It opens by itself on first run when no model is on disk and nothing is queued, from the Models page's "Download models" button, and from "Download more models" at the foot of the titlebar downloads menu (titled "Download models" there). A wide white sheet (up to 820px, 16px radius, pop shadow) with a 19px/600 title, a 13px `text-2` lede naming where models run, and a quick-select row: a muted "Select" label followed by plain buttons Recommended, Everything that fits and None. Rows are checkbox labels on a 9px-radius grid: violet checkbox, 32px logo tile (8px radius, `fill` behind), name at 600 with a Recommended chip only on recommended models (solid violet with white text once ticked, so it never sinks into the wash), a `text-2` tagline clamped to two lines, a 12px `text-2` line naming what it reads and its size ("Reads text and images. 4B parameters."), and a right-aligned status (download size in tabular `text-2`, or an "On this computer" green chip, "In the queue" violet chip, or the neutral fit reason). Rows hover to `fill`; a ticked row takes the violet wash. Models that do not fit this computer keep `text-2` text with a greyed logo, are disabled and never hover. On first run the recommended models start ticked. The sheet opens with focus on the first checkbox, never on Download, so Enter cannot start a multi-gigabyte download; Download shows "Queuing" and disables while the request is in flight. The `surface-2` footer reads "N models, size. X free on this computer." (the size in `text`, a not-enough-disk warning in orange ink) beside Not now (Cancel when opened later) and a primary "Download N models" button with a download icon, disabled until something is chosen.

### Setup Screens
The desktop app's first-run setup, after the macOS Installer and built from the studio's tokens (`desktop/installer/assets/tokens.css` is generated from `ui/styles.css` at every build, so setup cannot drift from the studio).
- **Step rail:** Welcome, Where models run, Install, Ready at 500 weight in `text-2`, each led by a 9px dot: an outlined ring when upcoming, a violet dot on a translucent grey-violet row (7px radius) when current, a green dot with a white check when done.
- **Footer bar:** `surface-2` with a hairline top, an optional note on the left, then Back (secondary) and the primary button (30px, at least 96px wide). The bar is 59px tall on every step so the frame never jumps.
- **Hardware rows:** a grouped list with 52px rows: a 30px rounded icon tile (violet wash and violet icon for GPUs, `fill` otherwise), a 600 name over a 12.5px `text-2` line, and an optional value or orange "Experimental" chip. While checking, rows show pulsing skeleton bars. Warnings and errors below use orange or red notes.
- **Radio cards:** one full-width card per device (12px radius, 16px padding, card shadow plus hairline ring): a radio, a 40px icon tile (solid violet with a white icon for GPUs), the title naming where models run ("NVIDIA GPU", "Apple GPU", "Intel GPU", "Processor only") at 15px/600 with Recommended (solid violet once selected) or Experimental chips, a line starting with the hardware's name, one sentence on what it is good for, and the install size. Selected turns the card violet-wash with a 1.5px violet ring and fills the radio; arrow keys move the choice.
- **Install progress:** a 14.5px/600 label with elapsed time right-aligned in tabular `text-2`, then a 6px `fill` bar with a violet fill that eases over 600ms; while working, a soft white sweep runs across the fill. Below, a checklist of steps with 18px marks: an outlined ring when pending, a violet spinner arc when active, a green disc with a white check when done, a red disc with a white cross when failed (its label turns `text` at 500 and the bar turns red). A "Details" disclosure with a rotating chevron opens the log as 11.5px mono in a `surface-2` well; it opens by itself on failure, and the footer then offers Copy details, Back and Try again.
- **Ready:** a 56px green disc with a white check above "Bud Decision Studio is ready", a grouped row for the device chosen, and a violet-wash "next up" panel with a 34px round violet icon that says the model chooser comes next.
- **Launch splash:** later launches show the mark, the name and an indeterminate bar while the studio starts. On failure the message ends with "Try again, or run setup again to repair the engine.", the log sits in a white well, and Copy details, Run setup again and Try again follow.
- **Launch splash:** on later launches, the 56px Bud mark, the name at 20px, a status line in `text-2` and a 200px indeterminate bar. On failure, the log shows in a white well with Run setup again and a primary Try again.

### Decision Figure
The signature component. A white 12px card with the question in 13px `text-2`, a certainty chip at the right, the answer at 22px/650 with its percentage at 15px, then the plot for the question type: horizontal bars on a shared 0 to 100% track with a 25% grid, a yes/no gauge from both ends with a dashed midline, a histogram with an average-position ring marker, or a number plot with an 80% band and an estimate line. Resting options use `data-1`, the runner-up `data-2`, the answer `data-3`; below the act threshold the answer turns orange. A `line-2` rule separates the caption: one plain sentence, confidence with a glossary term, and one verdict (Act automatically in green or Ask a human in orange). Bars grow and digits roll in over 520ms.

### Motion
UI state changes take 160ms, data 520ms, both on `cubic-bezier(0.22, 1, 0.36, 1)`; the palette enters in 180ms and toasts in 220ms. Question-type tiles lift in 120ms. Setup pages fade up 4px in 280ms, and setup progress uses a 1.4s sweep, a 1.3s indeterminate slide and a 0.8s spinner. Every animation and transition is switched off under `prefers-reduced-motion`, and figures draw in their final state.

## Do's and Don'ts

### Do:
- **Do** fill the window: sidebar 232px, titlebar 48px, status bar 30px, panes that scroll on their own.
- **Do** keep one job per screen and move detail into an inspector, segmented tab, disclosure row or popover.
- **Do** use Bud violet for the accent, the selection and the answer, and the violet data ramp (`data-1`, `data-2`, `data-3`) for all data.
- **Do** draw every answer on a shared 0 to 100% axis with a one-sentence caption and one verdict.
- **Do** start the font stack with the system font, then Inter; set changing numbers with tabular figures.
- **Do** lift surfaces with the card shadow (half-pixel ring plus soft shadow) and separate rows with inset `line-2` hairlines.
- **Do** write plain, sentence-case copy and give every technical term a dotted underline with a glossary tooltip.
- **Do** define every colour for both themes under the same token name and verify WCAG 2.2 AA contrast in each.
- **Do** switch off all motion under reduced motion.
- **Do** let the person choose before anything downloads; show the total and free disk, and dim and disable what does not fit this computer.
- **Do** say why a model cannot run here in place of its action ("Needs a GPU", "Too large here") rather than hiding it.

### Don't:
- **Don't** use orange for anything but "Ask a human" and caution, or green and red for anything but status.
- **Don't** use code syntax colours outside code and JSON blocks.
- **Don't** put em or en dashes in visible copy; write "to", a colon or a comma instead.
- **Don't** build busy walls of tables, repeated chips and links, centred web-page columns or dashboard-card collages.
- **Don't** use `text-3` for text that must be read; it is for icons and decoration.
- **Don't** use hard, offset or coloured drop shadows, glows or colour gradients on surfaces.
- **Don't** add uppercase eyebrow labels or kickers above titles; section labels are sentence case.
- **Don't** redraw or recolour the Bud mark; brand rasters are crops or compositions of the supplied lockup.
